# v1.6.8

## Fixes

- Fix proactive history placeholder: replace the opaque `[主动对话]` user-side marker with a semantically clear string so the model can correctly recognise that the paired assistant message was self-initiated rather than a response to a user message.
- Fix livingmemory conversation pollution: temporarily mask `cron_event.message_str` with the clean placeholder before firing `OnLLMRequestEvent` hooks, so livingmemory writes the placeholder instead of the full proactive trigger prompt into the conversation store. The generation prompt is restored immediately after hooks complete; retrieval quality is unaffected because livingmemory uses `req.prompt` for the memory search query.
- Sync proactive retrieval filter: `_is_natural_retrieval_line` now also blocks lines starting with `[灵犀主动` to prevent the new placeholder from leaking into retrieval queries.
