# 灵犀 · 主动对话插件

> 作者：灵犀 | 仓库：[astrbot_plugin_Spark](https://github.com/gongzhudeng/astrbot_plugin_Spark) | 主页：[gongzhudeng](https://github.com/gongzhudeng)

> **插件名**：`astrbot_plugin_Spark`

灵犀让 AI 像真人一样主动找你聊天——在对话沉寂一段时间后自然地重新开口，或者在你们正聊着的时候概率性地追加一句话，营造更真实的对话体验。

灵感参考：[astrbot_plugin_Conversa v3.0.0](https://github.com/Luna-channel/astrbot_plugin_Conversa) (Luna-channel)

---

## 核心特性

### 两步式主动对话

主动回复不再靠句号约定拦截，而是拆分为两步：

1. **智能判断** — 用独立 LLM 判断当前是否适合主动开口（可配置专用供应商和人格）
2. **内容生成** — 判断通过后才生成回复内容（同样可独立配置供应商和人格）

两步可使用不同模型，实现"小模型判断 + 大模型生成"的成本优化。

- 智能判断支持不限数量、可排序的独立回退模型列表
- 内容生成可选择使用插件独立回退列表，或跟随当前会话的 AstrBot 回退对话模型列表
- 判断与生成都会跳过重复、已删除或不可用的模型；生成主模型留空时继承当前对话模型

### 沉寂问候

与用户或 AI 最后一次聊天结束后，插件按互斥模式安排下一次候选问候：

- **对话热度**：根据共享热度在沉寂专属热场/冷场端点之间计算延迟
- **固定时间**：使用固定基准时间和单框随机浮动；支持 `0`、`5`、`+5`、`-5`、`-5~+5` 等写法
- **大模型判断**：达到“无聊天时间”后只调用一次判断模型；模型输出从最后聊天时间起算的总沉寂分钟数
- 模型返回 `0` 时本沉寂周期结束；返回正整数时保存一次性候选任务，插件重启后继续恢复
- 忙碌期间仍可完成沉寂判断；候选落入忙碌区间时顺延到结束后 5 分钟，实际发送前再次检查忙碌状态
- 判断或候选任务等待期间出现用户消息或普通 AI 回复时，旧周期立即失效并重新计时
- 用户可通过 `/灵犀 set after <小时>` 设置个人固定时间；该值只在固定时间模式生效

大模型判断用于选择下一次自然联系的等待时间，不提供可靠闹钟语义。聊天中的自然语言承诺只能作为判断上下文；需要保证准点执行的事项应使用 AstrBot 原生 cron 等任务系统。

### 对话热度系统

根据短期聊天密度和较长期交流余温动态调整沉寂问候与对话增强：

- **短期动量**反映刚才是否密集聊天，默认观察 45 分钟
- **长期余温**保留近 12 小时的交流影响，避免短期窗口结束后热度立即归零
- 两者默认按 `70% / 30%` 合成为同一个共享热度
- 沉寂问候与对话增强各自配置时间端点，并使用几何插值；热度为零/满热时严格落在冷场/热场端点
- 默认沉寂问候范围为 30～200 分钟；用户尚未回应上一条主动消息时不会继续发送沉寂问候或对话增强
- 提示词模板支持 `{heat_level}` 占位符（值为"冷/温/热"）

### 私聊对话增强

AI 正常回复用户后安排一次候选检查，由独立模式决定等待时间：

- **对话热度**：根据共享热度在增强专属热场/冷场端点之间计算
- **固定时间**：使用固定秒数和稳定随机浮动，支持与沉寂固定模式相同的单框语法
- 默认 100% 进入候选检查，不代表 100% 发送
- `ignore_judge` 可独立控制是否跳过通用“是/否”判断
- 用户或 AI 在等待期间产生新聊天时自动取消旧任务
- 用户尚未回应上一条主动消息时不会再次追发

### 无限每日定时问候

支持添加无限数量的每日问候项，每项独立配置：

- 时间来源可选固定时间，或忙碌日程中的活动开始/结束边界
- 活动名称包含任一关键词即匹配；可选择全部或第 `1/2/3...` 次匹配
- 每个匹配活动独立触发，同一分钟的多个任务不会互相覆盖
- 支持单框时间变化语法，偏移可自然跨日；错过目标分钟不会补发
- 聊天冷却同时参考用户消息、普通 AI 回复和所有主动消息
- `ignore_dnd` 仅控制是否绕过免打扰与忙碌状态，不能绕过聊天冷却
- 支持多个提示词模板随机选择

### 忙碌时段免打扰

与 `astrbot_plugin_busy_schedule` 深度集成：

- 忙碌时段自动静默，不主动发消息
- 每日问候可选择是否忽略忙碌状态

### 其他特性

- **免打扰时段**：全局或用户专属，支持跨天（如 23:00-07:00）
- **自动退订 & 重新激活**：不活跃用户自动退订，再次发消息自动恢复
- **Agent 订阅**：支持手动 / 自动 / AI 工具三种订阅方式
- **人格继承**：完整使用 AstrBot 人格系统，支持 `_special: select_persona` 下拉选择
- **图片状态面板**：`/主动状态` 以自适应图片展示订阅、热度、免打扰、每日问候和待触发任务，支持昼夜主题

## 安装

在 AstrBot WebUI → 插件市场中搜索 **灵犀** 安装，或手动将插件放入：

```
AstrBot/data/plugins/astrbot_plugin_Spark/
```

重启 AstrBot 后在 WebUI 中启用即可。

---

## 快速上手

1. **订阅会话**

   在聊天中发送：
   ```
   /灵犀 watch
   ```
   或在 WebUI 插件配置的「订阅用户列表」中添加会话 ID。

2. **等待触发**

   默认使用“对话热度”模式；也可以在插件配置中切换到“固定时间”或“大模型判断”。个人固定时间设置只在固定模式下生效：
   ```
   /灵犀 set after 1
   ```
   （设置为 1 小时后触发）

3. **（可选）设置免打扰**
   ```
   /灵犀 set quiet 23:00-07:00
   ```

## 配置说明

所有配置在 AstrBot WebUI → 插件配置中修改。

### 基础设置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 订阅方式 | `manual` | `auto` / `manual` / `agent` |
| 免打扰时段 | 空 | 格式 `HH:MM-HH:MM`，支持跨天 |
| 自动退订天数 | 3 | 用户连续无回复天数后自动退订，0 禁用 |
| 回复间隔（秒） | 20 | 多个主动回复之间的间隔 |
| 主动状态图片主题 | 自动切换 | 07:00-18:59 使用白天主题，其余时间使用夜间主题；也可固定主题 |

### 主动对话设置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用智能判断 | 是 | 是否用 LLM 判断是否适合主动开口 |
| 判断模型 / 回退模型 | 当前对话模型 / 空 | 仅用于普通“是/否”智能判断；判断失败时按配置顺序切换 |
| 判断步骤上下文轮数 | 3 | 普通智能判断和沉寂判断共用；1 轮=用户+AI 各 1 条 |
| 生成模型 | 当前对话模型 | 留空时继承当前会话模型 |
| 生成回退来源 | 插件独立回退 | 可切换为跟随 AstrBot 当前会话的回退对话模型列表 |
| 生成回退模型 | 空 | 插件独立模式下按配置顺序切换，数量不限 |
| 生成用人格 | 空 | 下拉选择生成步骤使用的人格（空=主人格） |

### 沉寂问候

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用 | 开 | 总开关 |
| 模式 | 对话热度 | `对话热度` / `固定时间` / `大模型判断`，只读取当前模式字段 |
| 忽略智能判断 | 关 | 热度/固定模式到点后是否跳过通用“是/否”判断；不跳过模型延迟判断 |
| 固定沉寂时间 / 浮动 | 1200 / `30` | 仅固定时间模式使用；个人 `/灵犀 set after` 值优先 |
| 热场/冷场延迟 | 30 / 200 | 仅对话热度模式使用 |
| 无聊天时间 | 60 | 仅大模型判断模式使用；达到后每周期判断一次 |
| 沉寂判断模型 / 回退模型 | 当前会话模型 / 空 | 仅大模型判断模式使用；独立于“智能判断”中的模型配置 |
| 总沉寂时长范围 | 5～1440 | 正整数表示从最后聊天时间起算的总分钟数；`0` 始终表示本周期不创建任务 |
| 技术失败重试 | 5 | 模型不可用、空响应、非整数或越界时的重试分钟数 |
| 聊天冷却（分钟） | 10 | 到点后若距任意聊天活动不足此时间，则顺延到冷却结束；0 关闭 |
| 问候提示词模板 | 内置 1 个 | 综合处理话题延续、问候、近况、照片和语音 |

### 每日定时问候

支持无限添加问候项，每项包含：

| 字段 | 说明 |
|---|---|
| `enable` | 是否启用 |
| `trigger_source` | `固定时间` 使用固定时间；`日程活动` 使用忙碌日程活动边界 |
| `time` | 固定时间，格式 `HH:MM` |
| `activity_keywords` | 标签列表；活动名称包含任一关键词即匹配 |
| `activity_boundary` | 使用 `活动开始` 或 `活动结束` 时间 |
| `activity_trigger_interval_minutes` | 活动模式下同一条问候距上次成功送达的最小间隔（分钟）；0 表示关闭 |
| `prompt` | 问候语（支持占位符） |
| `cooldown_minutes` | 聊天冷却；未满足时直接跳过，不调用判断或生成模型 |
| `ignore_dnd` | 是否忽略免打扰和忙碌状态；无论取值如何都必须满足聊天冷却 |
| `jitter_minutes` | 单框时间变化：`0` 不变化，`5` 前后随机，`+5`/`-5` 固定延后/提前，带 `~` 的值表示随机区间 |

活动模式依赖 `astrbot_plugin_busy_schedule` 提供结构化日程。普通活动缺少结束时间属于异常数据；最后一项开放睡眠可以直接使用开始时间，其结束时间只有在下一日程周期首个普通活动可用时才能解析。选择结束边界但无法解析时，该次匹配会被跳过并记录日志，不会猜测或回退到其他时间。

时间变化允许自然跨日。每日任务只在目标分钟触发，插件启动晚于目标分钟或门禁未通过时不会补发。随机偏移使用稳定任务种子，插件重启不会改变当次目标时间。

### 对话热度

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 短期热度窗口（分钟） | 45 | 刚才聊天密度的快速动量；旧 `heat_window_minutes` 配置直接沿用 |
| 长期余温窗口（分钟） | 720 | 保留近 12 小时聊天影响，窗口外自然归零 |
| 短期热度权重 | 0.7 | 短期 70%、长期 30% |
| 满热所需消息数 | 10 | 数值越小，升温越快 |
| 热场/冷场延迟（分钟） | 30 / 200 | 两端之间使用非线性几何插值 |

### 私聊对话增强

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用 | 开 | 总开关 |
| 模式 | 对话热度 | `对话热度` 使用热/冷端点；`固定时间` 使用固定等待和随机浮动 |
| 忽略智能判断 | 关 | 开启后候选到点直接生成，关闭时复用通用“是/否”判断 |
| 固定等待 / 浮动（秒） | 120 / `30` | 仅固定时间模式使用，支持单框浮动语法 |
| 进入候选检查概率（%） | 100 | 每次普通回复后是否安排候选检查，不代表必然发送 |
| 热场/冷场等待（秒） | 45 / 600 | 仅对话热度模式使用 |

### 提示词占位符

所有提示词模板支持以下占位符：

| 占位符 | 含义 | 来源 |
|---|---|---|
| `{now}` | 当前时间 | Spark 内置 |
| `{last_chat_at}` | 本轮最后聊天的绝对时间（沉寂判断模板） | Spark 内置 |
| `{idle_elapsed_minutes}` | 本轮已沉寂的整数分钟数（沉寂判断模板） | Spark 内置 |
| `{idle_min_total_minutes}` / `{idle_max_total_minutes}` | 总沉寂时长协议的上下限（沉寂判断模板） | Spark 内置 |
| `{time_since_last_chat}` | 距离上次聊天过了多久 | Spark 内置 |
| `{last_user}` | 用户最后一条消息 | Spark 内置 |
| `{last_ai}` | AI 最后一条回复 | Spark 内置 |
| `{umo}` | 会话 ID | Spark 内置 |

| `{heat_level}` | 当前对话热度（冷/温/热） | Spark 内置 |
| `{busy_status}` / `{busy_periods}` | 当前忙碌状态与结构化忙碌时间线（沉寂判断模板） | busy_schedule 集成 |

> v1.4.0 起，节律插件（`astrbot_plugin_time_period_prompt`）、记忆召回（`astrbot_plugin_livingmemory`）、知识库等内容均通过 `OnLLMRequestEvent` 钩子自动注入，无需在提示词模板中手动添加占位符。如你之前配置了 `{time_period_prompt}`，请手动删除，否则会导致节律内容重复注入。

### 灵犀AI忙碌时段管理插件集成

本插件支持 [astrbot_plugin_busy_schedule](https://github.com/gongzhudeng/astrbot_plugin_busy_schedule)（灵犀AI忙碌时段管理）插件的提示词自动注入。

安装了忙碌时段管理插件后，本插件的主动对话会自动注入以下内容到 AI 的 system_prompt 中：
- 今日穿搭
- 今日日程安排
- 当前活动
- 下一个活动

沉寂判断模型可以在忙碌期间运行，但候选联系时间不得落在忙碌区间内；代码会在忙碌结束后 5 分钟再允许发送。
- 自定义注入提示词

无需任何配置，安装即生效。这使得主动对话的 system_prompt 与正常对话保持一致，共享 KV Cache，提高缓存命中率，降低 API 调用成本。

## 故障排查

**没有收到主动消息？**
- `/灵犀 debug` 确认订阅状态和插件是否启用
- 检查是否处于免打扰时段或忙碌时段
- 确认沉寂模式和对应参数是否已到（热度模式使用热/冷端点，固定模式使用固定时间，大模型模式需先达到无聊天阈值并通过整数分钟判断）

**消息内容不理想？**
- 在 WebUI 中修改提示词模板
- 尝试切换生成用人格
